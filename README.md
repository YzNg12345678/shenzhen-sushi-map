# 深圳 Omakase 跨境家庭选店地图

给**常住香港、熟悉 Omakase、会带伴侣或父母去深圳消费**的人：一家店是否**稳定**、是否适合**带父母**、是否值得**专程过关**。

核心不是“深圳有哪些 Omakase”，而是降低一次跨境家庭聚餐选错店的成本。无登录、无后端、无社区、无付费排序。

## 产品形态（单页，地图优先、移动优先）

主界面只有：**地图** + **搜索 / 一排核心筛选**（带父母、值得过关、近期稳定、人均、口岸、我的收藏/去过）+ **卡片列表** + **详情抽屉**。个人数据导入/导出/清空与数据说明收在右上角“设置”里。旧版的季节、比较、护照、数据管理等一级页面已移除。

- **三轴判断**：稳定性 / 带父母 / 过关价值，每轴只有 `高 / 中 / 低 / 待核实`，**不做不透明总分**；每轴显示来源数、最近资料日期与判定理由。
- **结论标签**（由三轴按固定规则得出）：值得专程过关 / 顺路可以吃 / 带父母优先 / 熟客尝新 / 近期状态不稳 / 资料不足，暂不下结论。
- **价格分开看**：正文说法 / 评论补充 / 酒水 / 高德人均 / 最终人均（待店家确认）。
- **正文与评论有分歧**会在对应轴上直接标出；负面反馈在卡片上有 ⚠ 提示。
- 无素材或高德未返回的字段一律显示“待核实”，不推测、不编造。

### 三轴规则（`lib/judge.ts`，有单元测试）

- 没有强证据 → `待核实`（只有旁证或超过 365 天的说法时仅展示、不下结论）。
- 强负面且没有任何正面 → `低`；强负面但有正面 → `中`（有分歧）。
- 至少 2 篇**不同来源**的详细、近期正面记述且无负面 → `高`；单一来源正面最高 `中`；有负面说法时不给 `高`。
- 小红书点赞/收藏/评论量**不参与判断，也不展示**。

## 数据来源、更新时间与未知字段

| 数据 | 来源 | 位置 |
| --- | --- | --- |
| 店铺位置、地址、电话、营业时间、人均 | 高德 JS API 实时检索（`AMap.PlaceSearch`） | 运行时，不落盘 |
| 小红书笔记元数据与摘要 | 工作秘书采集（`shared/xhs-collection/shenzhen-omakase-map/web-dataset.json`，2026-11-20 采集 30 篇） | `data/notes.json`（标题、去掉查询参数的来源链接、发布/采集日期、标签、我方一句话摘要） |
| 门店与三轴证据 | 人工逐条整理，每条证据引用一篇笔记 | `data/shops.json`（版本 `dataVersion`，当前 16 家门店） |
| 口岸坐标 | 高德 POI（约值） | `lib/ports.ts` |

- 30 篇笔记中 25 篇已关联到具体门店；5 篇因正文/标签没写店名而**未映射**，原因列在“设置 → 未能映射到门店的素材”。
- 只保留摘要和来源链接，不复制正文、评论、图片；`source_url` 中的 `xsec_token` 等查询参数已去除。
- **目前尚无素材回答**：主厨、舍利、一场人数/时长、预约与取消规则、座位与洗手间、熟食调整、实际口岸通行时间、香港同价位对比——这些一律显示“待核实”。口岸距离只是坐标直线距离估算。
- 素材覆盖有限（30 篇）：绝大多数店的“带父母”“过关价值”仍是待核实，这是如实的状态，不是缺陷。
- 更新素材：`node scripts/sync-xhs-notes.mjs [web-dataset.json 路径]` 会合并新笔记并保留已有人工字段，然后在 `data/shops.json` 补证据、递增 `dataVersion`。

## 安装与启动

要求 Node.js ≥ 20，包管理器 **pnpm**。

```bash
pnpm install --frozen-lockfile
cp .env.example .env.local     # 填入下面两个高德变量，.env.local 已被 Git 忽略
pnpm dev                       # 默认端口 3417，可用 PORT 覆盖
pnpm build && pnpm start       # 生产
```

- `NEXT_PUBLIC_AMAP_JS_KEY`：高德 JS API 2.0 Key
- `NEXT_PUBLIC_AMAP_SECURITY_JS_CODE`：对应安全密钥

`NEXT_PUBLIC_*` 在构建时内联，修改后需重新构建。详见 `docs/amap-config.md`。**不要提交或截图真实凭据。**

GitHub Pages 预览：`GITHUB_ACTIONS=true` 时 `next.config.ts` 切换为静态导出并带 `basePath`；页面是纯客户端，数据是 import 的静态 JSON，可直接部署，但构建环境需提供上述两个变量，高德控制台需放行对应域名。

## 隐私

- 个人收藏 / 去过 / 备注只存在本浏览器 localStorage（键 `shenzhen-omakase-map:v2`），不上传；唯一外部请求是高德 JS API。
- 设置里可 **导出 JSON**、**导入 JSON**（先校验，失败不改动现有数据，导入前自动留备份）、**清空**（二次确认）。清缓存/换浏览器会丢失数据，请定期导出。
- 旧版“深圳寿司地图”的本地数据（`shenzhen-sushi-map:v1`）在新键为空时会迁移其收藏/去过/私人备注，旧键保持不动。
- 因为 JS Key 会内联到前端，必须在高德控制台配置来源白名单。

## 已知限制

- 数据规模小：16 家已整理门店、30 篇笔记；高德检索的其余店（约 80 家）只有位置等事实，三轴全是“待核实”。
- 过关价值没有任何一家达到“高”（缺实际交通时间与香港同价位对比），所以“值得过关 高”筛选目前会得到空状态。
- 同一品牌多家分店时，笔记通常未写明分店，证据按品牌共享并提示“分店待核实”。
- 门店关键词按名称匹配高德 POI，改名或新店需更新 `data/shops.json` 的 `keywords`。
- 高德检索有限流，偶尔部分检索失败（页面会提示“结果可能不完整”）；E2E 依赖真实高德网络与额度。
- 手机上详情抽屉会覆盖大部分地图，关闭后恢复。
